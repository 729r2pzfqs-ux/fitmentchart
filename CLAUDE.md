# fitmentchart.com

Vehicle fitment and specs database: bolt patterns, towing, oil, tires, battery
group and wiper sizes by year/make/model. Python + Jinja2 generate a static site
into `docs/`, which GitHub Pages serves.

## Layout

```
pipeline/            numbered steps, run in order; each is idempotent
  common.py          paths, config loading, cached HTTP (data/cache/http), IO
  01_skeleton_vpic.py      makes/models/years + body type   -> data/sources/vpic/, data/models/
  02_fueleconomy.py        engines + MPG (EPA vehicles.csv) + rated HP (EPA test-car lists) -> data/sources/fueleconomy/
  03_cvs_dimensions.py     NHTSA Canadian Vehicle Specs (dims, weight) -> data/sources/cvs/
  04_ankusi_wheels.py      bolt pattern / centre bore / OE wheel (ANKUSI, CC BY 4.0) -> data/sources/ankusi/
  05_manuals_extract.py    validates data/manuals/<make>/<model>.yaml (curated, quoted OEM extracts) -> data/sources/manuals/
  06_nhtsa_safety.py       recalls, complaints, NCAP ratings -> data/sources/nhtsa/
  07_merge_qa.py           data/sources/* -> data/models/*.json, then runs qa.py and writes data/qa_report.{json,md}
data/
  makes.yaml         canonical makes + per-source model-name match rules (the one place to add a model)
  generations.yaml   generation boundaries (also drives wheel-spec inference)
  asins.yaml         spec value -> affiliate products (hand-verified only)
  manuals/           towing/tires/oil/battery/wipers per model, each value cited (doc, page, verbatim quote); see manuals/README.md
  sources/<src>/<make>/<model>.json   per-source extracts (committed, diffable)
  models/<make>/<model>.json          merged output consumed by build.py
  cache/             raw downloads + HTTP cache (gitignored)
qa.py                quality gates (07 runs it; build.py refuses to build if it fails)
build.py             renders docs/: all Jinja2 templates, CSS and JS are inline strings in build.py (DictLoader)
                     pages: / , /<make>/, /<make>/<model>/, /<make>/<model>/<year>/,
                     /<make>/<model>/<spec>/ (towing-capacity, bolt-pattern, oil-capacity, tire-size, battery-size,
                     wiper-size; built only when the spec has data), /guides/<slug>/, /about/ /sources/ /privacy/ /terms/, 404
                     plus sitemap.xml, robots.txt, ads.txt, search-index.json, CNAME, favicon/* copied to the root
```

## Running

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
for s in pipeline/0*.py; do .venv/bin/python "$s" || break; done
.venv/bin/python build.py
```

- Every step takes `--refresh` to bypass the cache and re-download.
- Steps 02-06 need step 01's output in `data/sources/vpic/`.

## Data rules

- Every value has to trace back to a fetched source. Never hand-type specs into `data/models/`; that file is regenerated by step 07.
- If a source has no value, leave the field empty. QA reports the gap; never guess.
- Wheel specs carry `basis`:
  - `exact`: an ANKUSI row for that exact year.
  - `generation`: every ANKUSI row inside the same generation agrees, so the value is carried to that generation's other years.
  - Overlap years (two generations on sale at once) are only filled when both generations agree.
- Model-name matching is per source in `makes.yaml`, because vPIC, EPA, NHTSA, CVS and ANKUSI all name models differently. When adding a model, check each source's actual strings first.
  - `former_make`: the brand a model used to be filed under (Ram 1500 was a Dodge; EPA keeps Dodge through 2012). Every step queries both.
  - ANKUSI `skip`: named rows contradicted for the US market, with a reason kept in `skipped_rows`. ANKUSI `pin`: rows that belong to one generation whatever their year says.
- The F-150 Lightning, Silverado EV, Ram 1500 REV and Ramcharger are excluded on purpose. They'll be separate models later.
- Corolla Cross, GR Corolla, Corolla Matrix, Camry Solara and Accord Crosstour are separate models, not covered by the Corolla/Camry/Accord pages.
- The Ram 1500's `model` is the bare "1500". `build.py` sets `m["short"]` ("Ram 1500") wherever a model name stands alone.
- Step 05 uses data in `data/manuals/*.yaml`, regenerated by `tools/manuals/` (see its README). Never hand-edit a value there without a cited page and quote.
  - Towing records are either one configuration row (GM 2005-2010 manuals, Jeep, Toyota rows) or the max per engine across cab/box/drive columns. The latter carry a `note` saying so.
  - Battery group size: only the 2024 F-150 Raptor is OEM (Ford spec sheet). Everything else is `confidence: low`: `tools/manuals/add_battery.py` for the first five models (gap-research values, corroborated where possible by autopadre.com rows) and `add_battery_autopadre.py` for the rest (autopadre.com rows only). Pages must show the "verify on your battery label" disclaimer.
  - Wipers come from GM manuals (OEM) where available, otherwise from Rain-X fitment pages (`aftermarket_fitment`). A position with more than one Rain-X length is left empty.
  - Known manual gaps:
    - Tacoma 2005-07, 2013 and 2026 (toyota.ca has no manual for those years).
    - Silverado towing 2015-18 and 2021+ (no GM guide found); 2021+ manuals not found.
    - F-150 owner manuals: none. Oil/tires come from Ford tech-spec sheets where they exist, else f150hub.com / tirepressure.com (`third_party_reference`).
    - Civic 2006+ (Honda's portal needs login).
    - Wrangler manuals only for 2005, 2016-18, 2021-23 and 2026. FCA/Stellantis media spec sheets (s3 chryslermedia.iconicweb.com) fill 2011-14, 2019, 2024-26; none found for 2006-10, 2015, 2020. 2025 is the Canadian sheet (US one 403s).
    - Known OEM conflicts, manual kept: 2016-17 2-door 3.73 towing (manual 3,500 vs spec sheet 2,000); 2026 6.4L oil (manual 7.5 qt vs sheet 7 qt).
    - quadratec.com is behind a bot check; battery-group claims from autopadre/forums were not used.
    - Camry oil/towing 2005-07 and Corolla oil/towing 2005-07: toyota.ca's API starts at MY2008, and assets.sia.toyota.com (which hosts the older PDFs) answered 403. Corolla 2008: the PDF (OM12B28U) has no text layer. Their tires for those years are third-party. Corolla 2012-13 manuals still print a 2.4L that EPA doesn't list; left out.
    - Ram towing 2005-06, 2008-10 and 2013 (2013's Stellantis PDF answered 403). Ram oil 2005 (no manual found) and the 2024-25 3.6L DT: the only value is the spec sheets' 6.0 qt, which every DT manual contradicts (5 qt). 1500 Classic: no tow chart, oil 2019 and 2022 only. Ram tire years without a Feature Availability sheet are third-party.
    - Known OEM conflicts, manual kept: Ram DT 3.6L oil (sheets 6.0 qt vs manuals 5 qt), DT 3.0L EcoDiesel oil (sheets 10.5 qt vs manuals 8.5 qt). As printed: Camry 2012 4.4 qt build-date split; Corolla 2023 sedan 2.0L 4.9 qt vs 4.4 qt elsewhere.
    - Model 3: tesla.com answers 403, so tires are third-party (tirepressure.com, Goodyear), and there is no towing record because the secondary sources conflict. Rain-X and autopadre don't list it, so no wipers or battery. EPA test cars give EVs no displacement, so no HP.

## Site build notes

- Settings at the top of build.py: `ADSENSE_PUB` (set), `GA_ID` (empty = no GA tags; the privacy page mentions GA only when it's set), `AD_SLOTS` (empty = auto ads only), `CONTACT_EMAIL` info@fitmentchart.com. Never use a personal email.
- Titles must stay under 60 chars (`TITLE_MAX`); `render()` adds " | FitmentChart" only when it still fits. Descriptions are trimmed to 160 chars, preferring a sentence end. Write descriptions answer-first (lead with the value, e.g. "The 2026 Tacoma uses 24\" driver…"). Titles and descriptions must stay unique; check with a page audit after template changes.
- Dates shown on pages are real, not the build date: `POLICY_UPDATED` (privacy/terms, bump by hand when their text changes), each guide's `reviewed`, and sitemap `lastmod` from the model JSON's `updated`.
- 404.html is `noindex` with no canonical.
- Badges: `low confidence` (battery `confidence: low`) and `third-party` (every source is third_party_reference/aftermarket_fitment). Battery sections always show the "Verify group size…" disclaimer.
- Favicons live in `favicon/` (committed) and build.py copies them to the site root. Regenerate with `python3 scripts/make_favicons.py` (needs rsvg-convert + ImageMagick). The icon is a wheel hub with a 5-lug bolt pattern; 16/32 px use a bolder variant, and apple-touch-icon is full-bleed.
- Breadcrumbs: pass `crumbs=[(href, label), …]` to `render()`. It draws the visible trail and the matching BreadcrumbList JSON-LD. Year = Home › Make › Model › Year; spec = Home › Make › Model › Spec. Only the home page has none.
- All-electric models (`is_ev`) get MPGe labels and no towing or oil in titles and tables.
- Local preview: `python3 -m http.server 8765 -d docs`.

## Source notes / gotchas

- Respect refusals: use the pipeline's own User-Agent, and treat a 403, bot check or login as a gap. Don't spoof a browser, and don't take a blocked document from another host.
- ANKUSI: the GitHub repos (`david025445/ankusi-wheel-fitment-dataset`, `-data`) returned 404 as of 2026-10-13, and the figshare record (DOI 10.6084/m9.figshare.33921994) as of 2026-11-01. Step 04 tries GitHub, then figshare, then the Hugging Face mirror, which is the live source. The mirror's CSV starts with a BOM.
  - Corolla rows for 2004-05 (4x100) and 2019+ (5x114.3) carry non-US specs and are skipped, so the 12th generation has no bolt pattern. The sparse Accord rows leave 2005-12 and 2018-22 empty.
  - Licence: CC BY 4.0. Pages must credit "ANKUSI Wheel Fitment Dataset" with a link.
  - The year column can be a range (`2017-2025`, en dash too).
  - `oe_wheel` is free text.
- EPA `vehicles.csv` has no horsepower. HP comes from the EPA "Data on Cars Used for Testing Fuel Economy" files. Those are scraped from the EPA page, so the file URLs change.
  - There's one file per model year: CSV up to 2016, XLSX after.
  - 2005-2009 use the old column names: `CL_NM` carline, `GBE_CID_MSR` displacement in cubic inches, a fuel code, and the manufacturer instead of the make.
  - Joining: test cars have no turbo flag, so displacement + cylinders can't tell a 2.0 from a 2.0 turbo. The primary join matches the test result (FTP/HWY, rounded to 0.1 mpg) to vehicles.csv `UCity`/`UHighway` within 0.6%.
  - Fallback is model-name tokens. `FFV` stays a meaningful token: Ford's "F-150 FFV" separates the 3.5 NA from the EcoBoost.
  - `hp_match` records the method: `fe` / `name` / `mixed`.
  - The test-car data has manufacturer typos. The 2018 F-150 2.7L lists "400" HP, which is its torque. `reject_hp_outliers` moves values that contradict both neighbouring years into `hp_rejected`. It never substitutes a value.
  - GM is absent from the 2010 file entirely, so 2010 Silverado HP is a real gap.
  - The per-year test-car cache is keyed by the make list, so adding a make re-reads the files instead of reusing an extract without it.
- NHTSA recall/complaint model names drift by year ("SILVERADO" → "SILVERADO 1500" / "SILVERADO LD 1500"; "WRANGLER" + "WRANGLER UNLIMITED").
  - Step 06 discovers the names via `/products/vehicle/models`, adds the `always` names from makes.yaml, queries each one, and dedupes by campaign number / ODI number.
  - The discovery list is incomplete: 2010 shows only "TACOMA ACCESS CAB" etc., while the recalls are filed under plain "TACOMA".
  - The recalls endpoint answers HTTP 400 with a valid empty JSON body for a name with no recalls. `get_json(ok_status=...)` accepts that.
- NHTSA campaign serials can hold letters (21V00D000 is a real Model 3 recall).
- NCAP before MY2011 has no overall rating, only frontal / side / rollover stars.
- Pre-2019 NHTSA "SILVERADO" records can include HD trucks. They can't be separated.
- NHTSA APIs sometimes return an empty 200 body. `common.get_json` retries with backoff.
- CVS (`GetCanadianVehicleSpecifications`) values are metric: cm and kg. Step 03 converts them to mm and inches.
  - The 2005-06 Wrangler is listed as "TJ ...".
  - `measured_model_year` is often older than the query year, because CVS reuses measurements for unchanged years.
- ANKUSI is a sparse sample of years and trims, so most years are filled by generation inference.
  - Regional rows tagged [EU] / [UK] are skipped.
  - The Civic Type R's 5x120 is kept as a `trim_exceptions` entry; the Civic itself is 5x114.3.
